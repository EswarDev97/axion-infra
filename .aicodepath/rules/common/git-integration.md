# Git Integration and Auto-Commit

**Purpose**: Automate commits at strategic workflow points with validation

**Commit Points**:
1. After Design Stages Complete (per-unit)
2. After Code Generation (per-unit)
3. After Build and Test

---

## Overview

The Git Integration system automatically commits code at strategic points in the AICodePath workflow, ensuring that progress is tracked and can be resumed across sessions. All commits are validated against guidelines before being created.

---

## Commit Points

### 1. After Design Stages Complete (per-unit)

**Trigger**: When all design stages for a unit are approved

**What to Commit**:
- Functional design documents
- NFR design documents
- Database design documents
- Infrastructure design documents
- AI implementation design documents
- Any other design artifacts

**Commit Message Format**:
```
docs(cr-{number}/{unit}): add design artifacts

{Summary of design decisions}

Artifacts created:
- aicodepath-docs/construction/{unit}/functional-design/
- aicodepath-docs/construction/{unit}/database-design/
- aicodepath-docs/construction/{unit}/[other-design-folders]/

Design decisions:
- {Key decision 1}
- {Key decision 2}

Generated by AICodePath workflow
```

**Example**:
```
docs(cr-001/user-service): add design artifacts

Design documents for user service including functional design,
database schema with lookup tables, and API specifications.

Artifacts created:
- aicodepath-docs/construction/user-service/functional-design/
- aicodepath-docs/construction/user-service/database-design/

Design decisions:
- Using bcrypt for password hashing
- Lookup tables for user status and roles
- JWT for authentication tokens

Generated by AICodePath workflow
```

---

### 2. After Code Generation (per-unit)

**Trigger**: When code generation for a unit is approved

**What to Commit**:
- Generated source code
- Generated tests
- Configuration files
- Code documentation

**Pre-Commit Validation** (MANDATORY):
1. Run guideline validator on all files
2. Block commit if violations found
3. Log validation results in audit.md

**Commit Message Format**:
```
feat(cr-{number}/{unit}): implement {short description}

{Brief description of what was implemented}

Components:
- {Component/Service 1}
- {Component/Service 2}

Tests:
- {X} unit tests added
- Coverage: {X}% (if known)

Breaking Changes: {None/List}

Generated by AICodePath workflow
```

**Example**:
```
feat(cr-001/user-service): implement user authentication

Implemented user registration, login, and JWT-based authentication
with role-based access control.

Components:
- UserService - registration, login, password reset
- AuthService - JWT generation, validation
- UserRepository - data access with lookup tables

Tests:
- 24 unit tests added
- Coverage: 85%

Breaking Changes: None

Generated by AICodePath workflow
```

---

### 3. After Build and Test

**Trigger**: When build and test stage completes successfully

**Pre-Requisites**:
- All tests must pass
- Build must succeed
- No critical violations

**What to Commit**:
- Build and test documentation
- Test results (tests.json)
- Implementation status (implementation-status.json)
- Updated state files

**Commit Message Format**:
```
test(cr-{number}): verify build and tests pass

Build Status: SUCCESS
Test Results:
- Total: {X}
- Passed: {X}
- Failed: 0
- Coverage: {X}%

Quality Gates:
- [x] All unit tests pass
- [x] All integration tests pass
- [x] No critical security issues
- [x] Code coverage threshold met

Generated by AICodePath workflow
```

## Pre-Commit Validation

### Validation Checklist

Before ANY auto-commit, validate:

```markdown
## Pre-Commit Validation Checklist

### Guideline Compliance
- [ ] No hardcoded secrets detected
- [ ] No console.log/print statements
- [ ] No TODO without ticket reference
- [ ] Naming conventions followed
- [ ] No circular dependencies

### Code Quality
- [ ] All files properly formatted
- [ ] No syntax errors
- [ ] No linting errors (or only warnings)
- [ ] All imports resolved

### Tests (for code commits)
- [ ] All tests pass
- [ ] No test without assertions
- [ ] Coverage threshold met

### Database (if applicable)
- [ ] No ENUM types used
- [ ] Lookup tables for enumerated values
- [ ] Foreign keys indexed
```

### On Validation Failure

1. **DO NOT commit**
2. **Present violations**:

```markdown
## ⚠️ Commit Blocked - Violations Found

The following violations must be fixed before committing:

| File | Line | Violation | Severity |
|------|------|-----------|----------|
| src/auth.ts | 42 | Hardcoded secret | error |
| src/user.ts | 15 | console.log | warning |

**Error-level violations MUST be fixed.**
Warning-level violations SHOULD be fixed.

---

> **WHAT'S NEXT?**
>
> **Fix Violations** - I'll help fix these issues
> **Override** - Commit anyway (NOT RECOMMENDED for errors)
```

3. **Log in audit.md**

## State Tracking

### Update State After Commit

After each successful commit, update:

1. **context-state.json**:
```json
{
  "lastCommit": {
    "hash": "{short-hash}",
    "message": "{commit message}",
    "timestamp": "{ISO timestamp}",
    "type": "design|code|test"
  }
}
```

2. **implementation-status.json**:
```json
{
  "units": [{
    "commits": [
      {
        "hash": "{hash}",
        "type": "design",
        "timestamp": "{ISO timestamp}"
      },
      {
        "hash": "{hash}",
        "type": "code",
        "timestamp": "{ISO timestamp}"
      }
    ]
  }]
}
```

3. **audit.md**:
```markdown
## Git Commit - Code Generation
**Timestamp**: {ISO timestamp}
**Unit**: {unit-name}
**Commit**: {short-hash}
**Message**: feat(cr-XXX/{unit}): {description}
**Files Changed**: {count}
**Validation**: PASSED

---
```

## Rollback Support

### If Issues Discovered After Commit

1. **Identify the commit**:
```bash
git log --oneline -10
```

2. **View changes**:
```bash
git show {commit-hash}
```

3. **Revert if needed**:
```bash
git revert {commit-hash}
```

4. **Log rollback in audit.md**

## Integration with Code Generation

### Modified code-generation.md Steps

Add after Step 9 (original completion):

```markdown
## PART 3: COMMIT

### Step 10: Pre-Commit Validation

Before committing generated code:

1. **Run Guideline Validator**
   - Scan all generated files
   - Check against loaded guidelines
   - Collect violations

2. **If Violations Found**:
   - Present violations with fix suggestions
   - Wait for user to fix
   - Re-validate after fixes

3. **If No Violations**:
   - Proceed to commit

### Step 11: Auto-Commit Code

After validation passes:

1. **Stage Files**
   ```bash
   git add src/{unit-path}/
   git add tests/{unit-path}/
   git add aicodepath-docs/construction/{unit}/code/
   ```

2. **Create Commit**
   - Generate commit message using template
   - Execute git commit

3. **Update State Files**
   - Record commit hash in context-state.json
   - Update implementation-status.json
   - Log in audit.md

4. **Present Confirmation**
   ```markdown
   ## ✓ Code Committed Successfully

   **Commit**: {short-hash}
   **Message**: feat(cr-XXX/{unit}): {description}
   **Files**: {count} files, {lines} lines added

   Proceeding to next unit or Build and Test...

## Configuration

### Project-Specific Commit Settings

In `.aicodepath-overrides/config.json`:

```json
{
  "git": {
    "autoCommit": true,
    "commitPrefix": "PROJ-",
    "requireSignoff": false,
    "branchNaming": "feature/cr-{number}-{name}",
    "validationLevel": "error"
  }
}
```

### Disable Auto-Commit

To require manual commits:

```json
{
  "git": {
    "autoCommit": false
  }
}
```

## .claude Folder Version Control Decision

### Issue 10: Should .claude folder be added to .gitignore?

**Decision**: The `.claude/` folder should **NOT** be added to `.gitignore`.

### Rationale

The `.claude/` folder contains project-critical configuration that should be version-controlled:

| File | Purpose | Commit? |
|------|---------|---------|
| `hooks.json` | Hook registry and configuration | YES |
| `settings.local.json` | Project-specific permissions and hook config | YES |
| `skills.json` | Skill definitions | YES |
| `hooks/damage-control/patterns.yaml` | Security patterns | YES |

### Why Version Control is Important

1. **Hooks define project-specific validation rules** - Different projects may need different validation
2. **Damage control patterns are security-critical** - Protect the project from destructive commands
3. **Settings contain workflow-specific permissions** - Team needs consistent configuration
4. **These files define how AICodePath behaves** - Must be shared across team members

### What IS Gitignored

These are correctly ignored in `.gitignore`:
- `aicodepath-docs/` - Generated artifacts (state files, audit logs)
- `aidlc-docs/` - Project documentation (if generated)
- `node_modules/` - Dependencies
- `tmp/` - Temporary files

### Current .gitignore

```
node_modules
tmp
aicodepath-docs
aidlc-docs
```

### Migration Note

If migrating an existing project:
1. Remove `.claude/` from `.gitignore` if present
2. Commit the `.claude/` folder contents
3. Document any environment-specific settings separately
